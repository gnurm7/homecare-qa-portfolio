# BUG-001 — API accepts zero-room booking in training bug mode

**Origin:** deliberately seeded training defect, not a finding in a third-party product.
**Severity:** Medium in this demo. **Suggested priority:** High, because it violates a booking rule; priority is a proposal, not a team decision.
**Requirement:** [R2](requirements.md#r2). **Layer:** backend validation. **Environment:** Node.js 24; BUG_MODE=1.

## Steps
1. Start `BUG_MODE=1 npm start` (PowerShell: `$env:BUG_MODE="1"; npm start`).
2. POST `http://127.0.0.1:3000/api/bookings` with JSON:
   `{"name":"Demo User","serviceId":"cleaning","rooms":0}`.
3. Inspect status and body.

**Expected:** 400 and a validation message; no booking created.
**Actual:** 201, confirmed status, rooms 0, total 0.
**Root cause:** bug-mode lower-bound check accepts 0. Default mode enforces >=1.
**Verification:** the BUG-001 automated test starts both modes and asserts the erroneous 201 in bug mode and correct 400 in default mode. A passing reproduction check means the seeded defect was observed, not that bug mode is correct.
**Lifecycle demonstrated:** seeded → reproduced → cause identified → corrected default verified. No real issue-tracker history is implied.
